## Recorded Issues

### [STAGE-1] 2026-07-25 — Spring Boot 4.0.6 Non-Standard Test Starters
**Problem**: The scaffold used Spring Boot 4.0.6 milestone with non-standard test starters:
`spring-boot-starter-data-jpa-test`, `spring-boot-starter-webmvc-test`, `spring-boot-starter-thymeleaf-test`, `spring-boot-starter-security-test` — none of these exist in Maven Central.

**Root Cause**: Spring Boot 4.x is not yet GA. These artifact IDs were incorrectly generated by the Spring Initializr preview.

**Solution**: Downgraded to stable **Spring Boot 3.4.5**. Replaced all non-standard test starters with the canonical:
- `spring-boot-starter-test` (includes JUnit 5, Mockito, AssertJ)
- `spring-security-test` (separate artifact)
- H2 in-memory DB for repository tests

**Prevention**: Always use the latest stable GA Spring Boot version. Never use milestone/RC versions in production projects unless explicitly required.

### [STAGE-1] 2026-07-25 — DATABASE_URL Format for Neon PostgreSQL Driver Rejection
**Problem**: Neon PostgreSQL provides a JDBC URL containing inline credentials: `jdbc:postgresql://user:pass@host/db`. Spring Boot's Hikari pool driver failed to start with `Driver org.postgresql.Driver claims to not accept jdbcUrl`.

**Root Cause**: The standard PostgreSQL JDBC driver requires username and password as separate configuration parameters when parsed from URI format.

**Solution**: Integrated `dotenv-java` and added dynamic URI parsing in `EventManagementSystemApplication.java`:
```java
Dotenv dotenv = Dotenv.configure().ignoreIfMissing().ignoreIfMalformed().load();
dotenv.entries().forEach(entry -> System.setProperty(entry.getKey(), entry.getValue()));
// Extract username & password from DATABASE_URL and sanitize JDBC connection URL
```

**Prevention**: Always parse dynamic cloud database URLs containing embedded basic auth into distinct `spring.datasource.username`, `password`, and `url` system properties before launching SpringApplication context.

### [STAGE-2] 2026-07-25 — PostgreSQL JPQL Null Parameter `lower(bytea)` Error
**Problem**: Event search query failed with `org.springframework.dao.InvalidDataAccessResourceUsageException: ERROR: function lower(bytea) does not exist`.

**Root Cause**: When binding nullable parameter values (`:keyword IS NULL OR LOWER(e.title) LIKE LOWER(CONCAT('%', :keyword, '%'))`), PostgreSQL infers null JPQL parameters as `bytea` type, causing function signature mismatches.

**Solution**: Updated JPQL in `EventRepository.java` to explicitly cast parameters:
`CAST(:keyword AS String)` and `CAST(:dateFrom AS timestamp)`.

**Prevention**: Always apply explicit `CAST(:param AS String)` / `CAST(:param AS timestamp)` when writing JPQL queries with nullable search parameters for PostgreSQL.

### [STAGE-12] 2026-07-25 — Overbooking Race Condition in Event Capacity
**Problem**: High concurrent user signups for an event with 1 seat remaining caused multiple registrations to succeed, exceeding max capacity.

**Root Cause**: Read-modify-write pattern in memory without database lock allowed parallel threads to evaluate `event.isAvailable()` simultaneously before writing increments.

**Solution**: Added `@Lock(LockModeType.PESSIMISTIC_WRITE)` query (`findByIdWithLock`) and atomic SQL count update (`atomicIncrementCount` with condition `registrationCount < capacity`) in `EventRepository` and `RegistrationServiceImpl`.

**Prevention**: Never handle concurrent state increments using in-memory Java state alone; rely on DB-level pessimistic write locks and atomic SQL conditional updates.

### [STAGE-14] 2026-07-25 — `LazyInitializationException` on Event Detail Page Rendering
**Problem**: Opening the event detail page (`GET /events/{id}`) failed with a 500 error / page load crash.

**Root Cause**: `EventServiceImpl.findById(id)` called default `EventRepository.findById(id)` which loaded `speakers` and `createdBy` lazily. When Thymeleaf evaluated `event.speakers` in `detail.html`, the Hibernate session was already closed outside `@Transactional`, causing `LazyInitializationException`.

**Solution**:
1. Added `@EntityGraph(attributePaths = {"speakers", "createdBy"})` method `findDetailById(id)` in `EventRepository.java`.
2. Updated `EventServiceImpl.findById(id)` to call `eventRepository.findDetailById(id)`.
3. Added null/empty defensive check on `speaker.name` in `detail.html`.

**Prevention**: When rendering entities with LAZY collections in server-side view templates (Thymeleaf), fetch child associations eagerly via `@EntityGraph` in the repository layer.

### [STAGE-15] 2026-07-25 — Missing Test Mock Beans & Test Context Configuration on Feature Additions
**Problem**: Adding `AttendanceService` to `EventController` and new fields/services broken `EventControllerTest`, `EventServiceTest`, and `EventManagementSystemApplicationTests`.

**Root Cause**:
1. Controller slices (`@WebMvcTest(EventController.class)`) missed `@MockitoBean AttendanceService`.
2. Test fixtures in `EventServiceTest` and `RegistrationServiceTest` created `Event` instances without the newly required `endDate` field, causing `NullPointerException` when `Event.getStatus()` evaluated status.
3. `EventManagementSystemApplicationTests` attempted full context load without `@ActiveProfiles("test")`, attempting real DB connection.

**Solution**:
1. Added `@MockitoBean AttendanceService` to `EventControllerTest`.
2. Added `endDate` field to all `Event` builder test fixtures.
3. Added `@ActiveProfiles("test")` to `EventManagementSystemApplicationTests`.

**Prevention**: Whenever adding new mandatory entity fields or controller/service dependencies, immediately update test fixtures and mock beans across all unit and slice test classes.

## Rules Derived From This Context
1. Use stable Spring Boot GA releases only.
2. All secrets → environment variables → loaded via `dotenv-java` → referenced via `${VAR}` in YAML.
3. Explicitly cast JPQL nullable parameters to PostgreSQL types (`CAST(:var AS String)`).
4. Enforce DB pessimistic write locks and atomic updates for capacity-constrained operations.
5. Fetch LAZY associations eagerly via `@EntityGraph` in repository queries when rendering in Thymeleaf templates.
6. Flyway handles schema — never use `ddl-auto: create` in production.
7. H2 is test-only; always annotate full context integration tests with `@ActiveProfiles("test")`.
8. Update test fixtures and mock dependencies immediately whenever model schemas or service interfaces expand.
